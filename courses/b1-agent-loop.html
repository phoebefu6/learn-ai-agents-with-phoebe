The agent loop

What an agent actually is 7 min live

Both vendors who defined the field agree. OpenAI: agents are "systems that independently accomplish tasks on your behalf." Anthropic: agents are systems where "LLMs dynamically direct their own processes and tool usage." The key word in both is direct - the model chooses the next step. An app where your code chooses every step is a workflow. Both are useful; only one is an agent.

LiveThree components, four levers4 min▶

OpenAI's guide says every agent is three things: a model (the reasoning engine), tools (what it can touch), and instructions (the guidelines and guardrails it runs under). This course stretches that into the four levers you will toggle all night - because they are the four ways real agents fail:

  • Tools - without them the model answers from memory: fluent, confident, wrong.
  • Memory - without it, findings and instructions fall out of context mid-task.
  • Planning - without it, complex tasks get one-shot, half-done answers.
  • Guardrails - without them, the agent acts on things no one approved - including instructions hiding inside the data it reads.
Real world

The demo that lied. A team demoed an "analytics agent" to their exec - it answered every revenue question instantly and got a budget. In production someone checked a number against the warehouse: the agent had no database tool wired in and had been improvising figures the whole time. Nobody had asked which lever was on. You will run exactly this failure, on purpose, in Demo 1.

Self-studyWhen NOT to build an agent3 min read▶

OpenAI's guide is blunt: agents cost latency, money, and predictability - only reach for one when at least one of these holds:

  • Complex decision-making - judgment calls a rulebook cannot capture (refund approvals with context).
  • Difficult-to-maintain rules - the if/else forest nobody dares touch (vendor security reviews).
  • Heavy unstructured data - the task swims in documents and conversations (claim processing).

None of the three? Write deterministic code. Anthropic's essay opens with the same warning: the most successful agent builders use "simple, composable patterns" and add autonomy only when it demonstrably wins. "We could use an agent" is not a reason to.

Inside one turn of the loop 6 min live

Hugging Face teaches the loop's inner beat as Thought → Action → Observation. The model reasons about where it is (thought), emits a structured tool call (action), and the runtime feeds the result back into context (observation). Then the cycle repeats - with one more observation in context each time. That growing context IS the agent's working state: protect it, and you have protected the agent.

LiveWhere the four levers live in real stacks4 min▶

The levers are not this course's invention - they are what every serious framework ships, under different names. Learn the lever, and every framework becomes familiar:

  • Tools - Anthropic tool use / MCP servers · OpenAI function tools · HF "Tools". b2 wires Daybreak's MCP server in as the toolbox.
  • Memory - OpenAI SDK "Sessions" · LangGraph checkpointing + Store · Anthropic context management. b4.
  • Planning - Ng's Planning pattern · Anthropic's "transparency: show planning steps" principle. b5.
  • Guardrails - OpenAI's 7 guardrail types + human-in-the-loop · Agent SDK permission modes · LangGraph interrupts. b7.
Self-studyWorkflows vs agents is a dial, not a war3 min read▶

Anthropic's essay draws the line precisely: workflows orchestrate LLMs "through predefined code paths"; agents let the LLM direct its own process. Between the two extremes sit the five workflow patterns you build in b3 - prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer - each handing the model a little more of the steering wheel.

  • More autonomy = handles messier tasks, costs more, fails less predictably.
  • Less autonomy = cheaper, testable, boring - and boring is a feature in production.
  • The rule (both vendors): start at the workflow end; slide toward agent only when the task demonstrably demands it.

The 12-task scorecard - your course-long benchmark ★ 10 min · explore

Twelve real Daybreak ops tasks, from "what's our refund policy" to "send win-back emails". Start with every lever off and climb: watch WHICH tasks flip to ✓ with each lever, and read the failure text on the ones still red. This exact ladder - 1 → 5 → 7 → 10 → 12 - is the spine of the whole track: each session turns on the lever that unlocks the next rung.

All levers off: 1/12. Only pure arithmetic survives - an LLM alone is a reasoner, not an agent.

+ Tools: 5/12 (b2). Lookups work. But read task 12's failure - tools without guardrails introduced a brand-new danger.

+ Memory: 7/12 (b4). Multi-step comparisons stop losing their own findings.

+ Planning: 10/12 (b5). Diagnoses and reports - tasks that need decomposition - come alive.

+ Guardrails: 12/12 (b7). The two tasks that touch the outside world - sending email, reading untrusted tickets - finally pass safely.

Real world

This scorecard is a real practice, not a toy. Anthropic's agent-evals guidance says to start with 20-50 tasks drawn from real failures and track them continuously; Arize teaches the same decomposition for production agents. In b8 you will formalize this exact golden set - pass@k, trajectory checks, LLM-judges - and in b10 the assembled agent must hit 12/12 before you ship it.

Check yourself

Three questions before you go 🎯 ◐ 90 seconds

1 · What makes a system an agent rather than a workflow?

Anthropic's line: workflows run "predefined code paths"; agents "dynamically direct their own processes." Model size and tool count are irrelevant - who chooses the next step is everything.

2 · The agent quotes revenue that was never in any tool result. Which lever was off?

Hallucinated numbers are the tools-off signature. Planning-off gives shallow half-answers; guardrails-off gives unauthorized actions. Diagnose by lever, then fix.

3 · Why do both Anthropic and OpenAI say to try a workflow BEFORE an agent?

Predefined paths are cheaper, testable, and debuggable. Agents win when tasks are too varied for fixed paths - OpenAI's three criteria. Start simple, escalate deliberately.
